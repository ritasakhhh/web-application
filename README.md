# Практическая работа №1

## Вариант 22

Практическая работа по дисциплине
«Прикладная разработка серверных частей веб-приложений
на языке Python».

В данном этапе реализована модель слоя доступа к данным.

Данные хранятся только в оперативной памяти и не сохраняются
на диск.

Для представления записей используются кортежи.

## Структура данных

В модели используются три сущности:

### Actor

Структура записи:

```text
(
    uid,
    datetime,
    platform,
    user_agent
)
```
## Этап 2. RPC на основе TCP

Реализована служба удалённого вызова процедур на основе TCP.

Удалённо доступны 13 функций модели слоя доступа к данным.

### Структура запроса

Запрос состоит из:

- 3 байт — размер тела запроса;
- 1 байта — код операции;
- тела запроса в формате XML.

### Структура ответа

Ответ состоит из:

- 1 байта — версия протокола;
- 1 байта — код операции;
- 4 байт — размер тела ответа;
- тела ответа в формате XML.

Для числовых полей используется порядок байт от старшего
к младшему.

### Запуск сервера

```bash
py src/rpc_server.py
```
## Этап 3. Model-Based Testing

Для тестирования используется `RuleBasedStateMachine`
из библиотеки Hypothesis.

В `tests/test_rpc_mbt.py` реализованы отдельные правила
для всех 13 RPC-методов.

Состояние RPC-сервера сравнивается с состоянием упрощённой модели.
При ошибке выводится имя RPC-функции, на которой произошёл сбой.

Для тестов сервер автоматически запускается на порту `5001`.

Запуск тестов:

```powershell
$env:PYTHONPATH="src"
py -m unittest discover -s tests -p "test_*.py"
```

Проверка покрытия ветвей:

```powershell
py -m coverage run --branch -m unittest discover -s tests -p "test_*.py"
py -m coverage report -m
```

## Пример RPC-вызова

```python
client.create_actor("Windows", "Chrome")
```

Клиент отправляет запрос по TCP, сервер вызывает
`create_actor()` и возвращает результат клиенту.
